## :dart: O guia para alavancar a sua carreira

> Vuex é a biblioteca oficial de gerenciamento de estado do Vue.js: um "cofre" central onde os componentes leem e alteram dados de forma previsível, com mutations, actions e getters. Desde 2022 o próprio time do Vue recomenda **Pinia** como padrão para projetos novos — Vuex 3/4 segue mantido, mas sem novas funcionalidades. Este guia cobre os dois: os fundamentos de Vuex para quem mantém ou estuda projetos legados, e Pinia (a store oficial para Vue 3) para quem está começando hoje, com trilha de migração, cursos, ferramentas, comunidades e um capítulo de IA na prática.

## 💡 Nossa proposta

> A proposta deste guia é dar uma ideia sobre o atual panorama e guiá-lo se você estiver confuso sobre qual será o seu próximo aprendizado, sem influenciar você a seguir os 'hypes' e 'trends' do momento. Acreditamos que com um maior conhecimento das diferentes estruturas e soluções disponíveis poderá escolher a ferramenta que melhor se aplica às suas demandas. E lembre-se, 'hypes' e 'trends' nem sempre são as melhores opções.

## 🤖 IA na prática

Vuex e Pinia são bibliotecas pequenas e bem documentadas — exatamente o tipo de código onde um assistente de IA rende bem, desde que você valide contra a documentação oficial (a IA ainda confunde a sintaxe das duas).

**Para aprender**
- Peça para a IA **reescrever uma store Vuex (state/mutations/actions/getters) como uma store Pinia equivalente** e compare com o [guia oficial de migração](https://pinia.vuejs.org/cookbook/migration-vuex.html) — é o exercício mais direto para internalizar as diferenças.
- Cole um trecho de store e peça: *"essa lógica deveria estar numa getter, numa action ou num composable? explique o porquê"*.
- Peça exemplos comentados de **Options Store vs Setup Store** no Pinia e quando cada estilo faz mais sentido.
- Peça para explicar um erro comum do Vuex (ex.: mutar o state fora de uma mutation) e mostrar o mesmo erro (ou a ausência dele) em Pinia.

**Para trabalhar**
- Use [GitHub Copilot](https://github.com/features/copilot), [Cursor](https://cursor.com/) ou [Claude Code](https://code.claude.com/docs/en/overview) para gerar o boilerplate repetitivo de uma store nova (state tipado, getters, actions) a partir da descrição do domínio.
- Peça para a IA gerar **testes de store** (com `@pinia/testing` ou o utilitário de testes do Vuex) cobrindo os principais fluxos de actions.
- Ao migrar um projeto grande, peça para a IA mapear **todos os módulos Vuex de um diretório** e sugerir a divisão em stores Pinia — depois revise módulo a módulo, sem aceitar migrações em massa sem checar.

**Limites e boas práticas**
- IA mistura sintaxe de Vuex 3, Vuex 4 e Pinia com frequência (são APIs parecidas, mas não iguais). Sempre confirme contra a [documentação do Pinia](https://pinia.vuejs.org/api/) ou do [Vuex](https://vuex.vuejs.org/api/).
- Ela tende a sugerir `mapState`/`mapActions` (padrão Options API) mesmo em projetos que usam Composition API. Peça explicitamente o estilo que seu projeto usa.
- Não cole tokens, chaves de API ou dados de usuários reais que estejam guardados na store em ferramentas de IA sem checar a política da sua empresa.
- Entenda a store antes de aceitar: em produção, um bug de state mal migrado afeta a aplicação inteira.

**Bibliotecas de IA no ecossistema Vue**
- [Vercel AI SDK](https://ai-sdk.dev/) — SDK com suporte a Vue/Nuxt para construir interfaces com streaming de respostas de LLMs, frequentemente combinado com Pinia para guardar o histórico de conversa.
- [Anthropic TypeScript SDK](https://github.com/anthropics/anthropic-sdk-typescript) — SDK oficial para usar os modelos Claude a partir de uma aplicação Vue/Nuxt.
- [Claude Code](https://code.claude.com/docs/en/overview) — Agente de código no terminal, útil para migrações grandes de Vuex para Pinia.
